## 决策

1. 普通执行不再默认注入 `maxIterations=32` 和 `maxTokens=65536`。没有配置的维度表示未设置该预算，不用另一个更大的常量替代。
2. `IterationBudget.maxIterations` 改为可选。库调用、CLI、REPL 与 TUI 走相同的预算 owner。配置上下文或金额预算不会隐式附赠一次数上限；只有显式请求次数上限时才保留既有 final-report 请求。
3. 显式 `--max-iterations`、`--max-tokens`、金额及上下文硬门禁继续生效。既有设置文件中的数值仍被尊重，不改用户全局选择或配置。显式累计输出预算仍发送剩余额度，保持现有 CLI 兼容合同；默认 wire 省略该限制。
4. 单次生成与思考继续使用 provider/model 能力和用户明确配置。此次不凭经验添加统一的 16k/32k 单次上限，不降低 reasoning effort，也不把被截断的输出认作完整答复。
5. 对已声明的窗口，在 90% 处自动压缩；首次/resume 发送前也执行软阈值检查。上下文硬上限继续保持配置值。没有窗口声明时不猜测模型容量。
6. 压缩若未清除软阈值，则保持失败/无效 authoring 的探测锁存，避免每一轮反复摘要；已有有界硬门禁救援仍保留。压缩前后原始用户约束与工具配对不变。
7. 取消、权限、doom-loop、上下文拒绝、provider 错误继续有效；去掉两项默认预算不代表无条件无限执行，也不改变执行完成与质量验收的区别。

## Journal delivery contract

The execution journal is the sole owner of the optional internal `deliverySequence` input field. It allocates dense positive safe integers at dispatch, not at event creation: queued tool facts can arrive after newer text facts. A repeated event id receives its original sequence, even after thousands of later inputs. The reducer keeps one watermark and emits no commands for an already delivered position. Domain refusals consume their position; dispatch adopts that state so subsequent cancellation is not blocked by a gap.

Legacy inputs without positions retain the bounded opaque-id deduplication path, including its fail-closed overflow. Sequenced and opaque inputs cannot be mixed in one reducer state; invalid positions or gaps return typed `invalid_input`. The map indexes inputs already retained in the journal; this removes the artificial 4096-event runtime ceiling, not the memory cost of retaining a full journal. Runtime memory still grows with retained events.

This is internal replay metadata, not a CLI stream/v1 or session format change. Existing journals remain readable by the new reducer. New positioned debug journals require the new reducer for watermark semantics; older consumers may ignore extra fields but retain their old overflow behavior. No command, permission, provider schema, or tool outcome is reinterpreted. Round-trip replay and duplicate old tool request tests cover the compatibility boundary.
