# Trylo CLI 文档权威与过期清单

> 状态：已批准
> 最后更新：2026-09-16
> 决策来源：产品所有者明确指定 `TRYLO-LEARNING-AGENT-顶层架构与目标.md` 为最新总标准

## 1. 唯一最高标准

`TRYLO-LEARNING-AGENT-顶层架构与目标.md` 是当前产品目标与顶层架构的最高文档。它冻结的核心包括：

- Trylo 是 Learning Agent，用户学习、Agent 学习、Execution Substrate 同级；
- 学习控制板是与执行调度器平级的第二调度器，调度学习时机、方向和 token；
- 执行环与学习环并行，不嵌成一个大 while；
- 用户学习与 Agent 学习共用控制板但工单、权威和产物分家；
- 用户证据入口绑定执行当时的身份事实，学习环不得自造；
- 用户学习必须保留 Evidence → Eligibility → Conclusion → User Model/Latent → Policy → BehaviorDelta/Receipt 深链；
- Agent 学习覆盖 what/when/where/how，并同时承认 intra/inter；
- 学习不授权、不默认自改内核、不把沉默当同意、不把通用质量写成偏好。

用户明确决策高于本文；除此之外，任何下位文档与最高标准冲突时直接舍弃冲突部分，不做折中拼接。

学习议题上，`../03-学习意志/` 里**符合该目录 `禁止乱放.txt`** 的文档，视为产品所有者意志的书面记录，效力同「用户明确决策」。与本文已钉红线冲突时停工问所有者，不准施工 Agent 擅自折中，也不准把 STATE/脑暴往那个目录塞。

## 4. 工程产出如何解释

`02-分期工程产出/` 下日期化工作包、STATE、RUN、审计、HANDOFF、测试矩阵和外审报告是不可改写的过程证据。它们不因架构更新而失去事实价值，也不需要逐个改名；但其规范性主张只在当时上下文成立。

使用规则：

1. 可以引用它们证明“当时做了什么、测了什么、发现了什么”。
2. 不得引用它们证明“当前产品只能做什么”。
3. 旧工作包不得原样续跑；必须先由当前工作包重新声明有效边界。
4. 外审未关闭的问题继续有效，不能因上位架构变化而自动消失。
5. 文件夹 `P00`–`P09` 当前是归档坐标，不自动代表最新总体施工顺序。

## 5. 调研文档如何解释

`99-施工调研/传统CLI基底/` 是传统 CLI Execution Substrate 的必做机制证据。`open/report/` 是 Agent 学习九维机制证据。两类材料都属于参考层：

- 传统 CLI 调研回答 loop/provider/tools/session/surface 怎么可靠实现；
- Agent 学习调研回答 what/when/where/how 的候选机制；
- 研究项目没有某能力，不构成 Trylo 不做该能力的理由；
- 无许可证或限制性许可证的仓只读思想，不复制代码；
- 新工作包触碰 Agent 学习时必须先从 `open/report/00-INDEX-exploration-archives.md` 路由到相关维度，不得泛读后自由拼装。

## 6. 新文档准入规则

每份新架构或施工文档必须在开头回答：

1. 如何服务 Learning Agent 三块同级目标；
2. 是否触碰已冻结框架或仍开放机制；
3. 若只做传统 CLI，如何保证它是 Execution Substrate 而非产品定义；
4. 若触碰 Agent 学习，使用了 `open/report` 哪一维和哪些可运行机制；
5. 是否改变 Permission、证据入口、上场物或控制板调度权；
6. 与并行工作包的文件写入集是否相交。

未回答以上问题的工作包不得进入生产施工。
