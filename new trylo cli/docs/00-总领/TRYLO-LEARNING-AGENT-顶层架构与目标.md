## 讨论收口（框架层，2026-09-13～14）

以下是产品讨论里**已经口头钉住**的框架，写入本文以免下一轮再漂。具体机制（工单排序、预算单位、hold、字段、一拍怎么切）明确以后再立，不在本收口展开。

### 已定

1. **产品是学习 Agent。** 主角是学习，不是传统执行环。用户学习、Agent 学习、执行基底三块同级。没有学习的执行环只是底座。
2. **学习控制板是第二调度器。** 与执行调度器平级。调度「何时学、学哪一路、花多少 token」。调度主、账本从。不是人事状态机，不是第二个替用户干活的 Agent。后面省 token 的策略都挂在这块板上。权限和生产工具仍只认执行调度器。
3. **两条 Loop 并行，不嵌成一个大 while。**  
   - 执行环：干活、认上场内容、打点、听控制板调度令。  
   - 学习环：常转，由控制板花钱；没有新传感器也可以因自身时钟/积压而动。  
   执行侧钩子是传感器，不是学习主循环。
4. **两大学习同一块板、两路工单、产物分家。**  
   - 用户学习：整条链做深（Evidence → … → Policy），厚而稀、上场要瘦；不能收成 `user_rule`。  
   - Agent 学习：按 what / when / where 内部进化；过门才上场；卡住才 intra。  
   不把 User Model 和 Skill 合成一种学习资产。
5. **用户学习的证据入口绑在执行环上。** 「调取证据」指定的是前者：执行当时按身份把证据落下（哪次运行、当时发生了什么）。学习环不自造用户证据。不是指定「学习环每次跑用户管道再按执行身份检索一遍」（那一层以后再说）。
6. **红线不因大胆而撤：** 学习不授权、不改内核、沉默≠同意、通用质量不是偏好、采集关闭不偷学。Intra 写 task-local；升跨任务资产必须再过任务间验证门。
7. **学习施工必须先和产品所有者讨论。** 模型不准自己把学习包做宽。讨论过的脉络写入 `docs/03-学习意志/`（该目录是学习议题上的所有者意志书面记录，禁止当垃圾桶）。传统 CLI 仍可按 `docs/99-施工调研/传统CLI基底/` 施工，不必每包过所有者。
8. **提取和上场都是控制板的事。** 往提示词里无上限 append 经验卡，等于没有调度器。上场必须有硬顶。2026-09-16 收缩的第一包只做：延迟后的一张本轮约束卡，注入下一枪 `messages` 的短 system，turn 结束拿掉，跨 turn 不上场。卡更新、跨 turn 选卡、hold，以后再讨论。  
   （2026-09-16 第二轮细化：控制板不再亲自提取与挑卡，它只**点名子系统 + 给额度**；提取、编译上场、记账都在被点名的**方法子系统**内部完成。硬顶的形态从「只准一张」改为「上场预算」。见 §5.5。）

### 框架级仍未钉（下一步只谈框架，不谈机制）

讨论停在「先定整体框架、不要往细」。下列仍属同一高度、尚未口头收口：

- **上场物：** 学习 → 执行的接头。执行到底认什么冻结清单。文档后文若出现 Dispatch Image，只是讨论用语，**不算已定名称或已定内容表**。
- **共同经历 / 织物作为框架块：** 用户证据入口已定；「一次任务一份经历再分叉」、Agent 侧是否同一织物，尚未单独钉。
- **体内 vs 真外围：** 控制板和两环在 CLI runtime；Desktop / 安装器 / 宿主在外。最早问过，后面被主角问题盖过，未再口头收口。

两口钟（任务内 / 任务间）作为能力默认承认；怎么插、能不能 hold，算机制，未定。

## 0. 要做成什么

Trylo CLI 不是「更好用的 coding CLI」，也不是「传统 Agent + 外面挂学习」。

要做成：

> **一个真正的学习 Agent：用户学习和 Agent 学习与执行同级、同优先级；用户学习按 Personal Agent 做深；Agent 学习按自演化文献做成一定程度的内部进化（学什么、何时学、在哪学、怎么学）；执行是学习发生的场地和被改写的对象。**

成熟产品不做 intra、不做方法进化、不做验证准入、默认关记忆——那是他们要卖、不敢放。调研已经证明：论文侧这些环路有可跑的零训练形态。缺的是产品把它当主角，不是论文没方向。

传统 while-tool-loop 对着 `open/01-agent-cli-runtimes/` 抄熟做法，只补 **Execution Substrate**。它规定不了学习有多大胆。

约束只保留已经立过的红线，不当成「所以学习要薄」：

- 学习不授权
- 沉默 ≠ 同意
- 通用质量不是偏好
- 不把权重训练伪装成当前必做（权重级在地图上，不假装今天就有 GPU）
- 不把自改内核当默认进化手段（Gödel / DGM 改 `runner` 是禁区，**不是**内部进化的定义）

内部进化 ≠ 自改执行内核。内部进化 = **记忆、规则、技能、工作流、工具面、检查/奖励、路由，在经验压力下变体、验证、选择、回写。**

## 1. 主角换人

```text
错误图（套壳）：
  Execution Loop  ──挂──►  可选学习

本架构：
  ┌──────────────────────────────────────────────┐
  │              LEARNING AGENT                  │
  │                                              │
  │   User Intelligence       Agent Evolution    │
  │            ╲                 ╱               │
  │             ╲ Evidence Fabric╱               │
  │                                              │
  │      Execution Scheduler │ Learning Scheduler│
  │      （执行调度器）        │ （学习控制板）     │
  │            用户任务队列   │   学习工单队列     │
  │            模型/工具/审批 │   何时学/学什么    │
  │                          │   花多少 token    │
  │      Permission 只认执行调度器               │
  │      控制板支配学习预算与时机                  │
  └──────────────────────────────────────────────┘
```

三块 **产品优先级相同**。没有「先做传统 CLI，学习以后再说」。没有学习的执行环只是底座，不是 Trylo。

Learning Loop / 学习控制板 / 两大学习平面 **在 CLI runtime 内**。不是外围插件。控制板是与执行调度器平级的**第二调度器**，不是学习账本，也不是第二个替用户干活的 Agent。

真外围只有：Desktop 查看与高风险人审、工具安装器、CAD/Office 等宿主进程、远程、桌宠。生成、选择、启用、 intra/inter 进化在 Agent 体内。

运行时冲突次序（这是冲突消解，不是产品排序）：

```text
安全 / 数据完整性
> 本轮用户明令
> User Learning 已生效政策
> Agent 已启用方法 / skill / workflow
> 普通记忆事实
```

关掉学习，执行基底仍能跑——那是故障降级，**不是产品定义。** 产品定义是两大学习开着。

## 2. 两大学习，不要合成一个「Learning」

文献和用户学习文档本来就是两套问题。架构上必须分开，再在同一套进化控制器里汇合。

融合点是：**共同理解一次任务经历**，然后分别形成用户标准、项目事实和执行技能，最后在任务中一起使用。不是把 User Model 和 Skill 塞进同一种「学习资产」。

| | 用户学习 | Agent 学习 |
|---|---|---|
| 对象 | 这个人如何判断、何种反馈可靠、协作契约 | 这类活的方法、工具、工作流、检查 |
| 压缩风险 | 具体纠正被压成人格标签 | 轨迹被压成又一篇 SKILL.md 却无验证 |
| 权威 | 人；权威纠正最高 | 外部验证 / 检查器；自评不能转正 |
| 编译产物 | Runtime Policy Pack（怎么合作） | 技能 / 工作流 / 工具绑定 / recipe（怎么干活） |
| Intra | Ask-or-Act、当轮意图、trial、Cognition | 变体 → 验证 → task-local 策略 |
| Inter | User Model / Policy 更新、outcome、护照级迁移 | 记忆 / 技能 / 工作流 / 工具 / 检查进化 |

Agent 学习可以进化技能、工作流、工具、检查，**不能**从工具成败直接写 User Model。  
用户学习可以改变 Agent 怎么合作、怎么汇报、信用户哪一种验收，**不能**把「少审核」编译成跳过核心验证，也不能给 Agent 方法授权。

## 3. 用户学习 = Personal Agent / Usership（必须做深）

来源：`核心技术文档/` 理念基线、Evidence / Conclusion / User Model / Policy / Cognition / v0.2。  
不是 `user_rule` 四个字段，不是「纠正 → 规则 → 下次注入」。那只是链上最浅的一条快路径。

### 3.1 北极星与度量

> 减少下一次相似协作中，用户为获得正确合作方式而重新解释的成本。

它是：透明、条件化、分作用域、可撤销的 **协作契约编译系统**。  
它不是人格标签、不是无限聊天记忆、不是用沉默当满意、不是从历史批准推导未来授权、不是用「置信度高」替代「实际对用户有帮助」。

主指标是 **重复解释率**（同类机会上又被明确说了一遍的比例），不是模型条数、Evidence 条数、Cognition 回答率、confidence 均值、未改产物比例。

每条能进可执行理解的内容必须能回答：改哪个决策、什么条件适用、什么条件失效、证据是什么、用户怎样仅本次覆盖/暂停/纠正/撤销、用了是否真的少返工。答不上来的，最多当短期 trace 或候选。

### 3.2 长期定义与三阶段

基础模型可换。属于这个人的协作能力留在 Personal Agent 里：

```text
Human + Personal Agent + Available Foundation Model
= 实际工作能力
```

| 阶段 | 问题 |
|---|---|
| I Understand & Adapt | 理解我、适应我 |
| II Represent Me | 代表我去和其他 Agent 工作，用户不要变成 Team 的 Prompt Manager |
| III Grow With Me | 经授权后挑战用户，而不是永远顺着、把能力边界焊死 |

Stage I 里有 **两件不能混的事**：

| | Preference Learning | Engineering Adaptation |
|---|---|---|
| 问 | 没说全时，这个人更可能要什么 | 已知这个人之后，Agent 工程行为怎么改 |
| 价值 | 补全不完整需求 / 压缩重复规格 | 补 Human+Agent 组合的工程下限 |
| 例子 | 「好看一点」→ 低饱和、留白 | 前端秒批 + 事后 rollback → 自己测、让用户验产品行为 |
| 智能 | 主要走 Latent + Decision Governor | 主要走 Symbolic User Model → Policy |

「猜他要什么」和「因此我该怎么做工程」是两条路。混成一条偏好列表，用户学习就死了。

市场调研已点明核心风险：用户说「先看调用链」是方法，「公式不能写死」是验收标准，「先给结论」才是偏好。若全压成「用户喜欢严谨」，**丢掉的正是可执行信息**。

### 3.3 主链：禁止跳层

```text
Trace / Cognition / 真实执行行为
        ↓
Evidence          发生过什么（还不是规律）
        ↓
Eligibility       先修自己：偏好 vs 质量缺陷 vs 授权 vs 当前指令
        ↓
Conclusion        稳定规律、scope、冲突、关系、漂移
        ↓
User Model        专业协作判断（还不是 Agent 必须怎么做）
   ∥ Latent Preference   意图补全（并行）
        ↓
Policy Compiler   低频：编成结构化准则
        ↓
Runtime Resolver  高频：本任务选出 3–7 条
        ↓
Agent 行为差（BehaviorDelta / Commitment）
        ↓
Outcome / Receipt
        ↓
新的 Evidence
```

产品价值在第三步：

```text
发生了什么
→ 规律是什么
→ 这个规律在专业协作中意味着什么     ← User Model
→ 这一次工程里 Agent 因此怎么工作     ← Policy
```

把「少审核」直接收成一条规则，第三步直接没了。

每一层回答的问题不同，**禁止共用一个 confidence**。来源可信、推断合理、应用正确、实际有益是四个判断。

### 3.4 Evidence：底层、保守

只回答用户发生了什么、表达了什么、选择了什么。不回答「这个人是谁」。

三大来源，权不同：

- **Work**：approve / 打断 / rollback / 改产物 / 看到结果后改口 —— 最接近真实工程
- **Interaction**：明确偏好、纠正、选方案
- **Cognition**：Bootstrap 是强证据但不是自动真理；看过真实行为后再确认更强；**Authoritative Correction 最高治理，后台学习不得静默覆盖**

一条 Evidence 至少五问，不是一个 0.8：

1. 表达是否就是所记之意（semantic）
2. 对以后工程有多大价值（relevance）——喜欢某种食物 ≈ 0
3. 反馈时是否已看到真实结果（context informedness）
4. 治理有多强
5. scope 有多窄

Agent 自己的输出不能单独当 User Evidence。沉默 ≠ 同意。Raw 与 Inferred 必须分离。Store 可以大，运行时不应全量加载。

**与执行环的绑定（讨论已定）：** 用户证据在执行当时按身份落下。学习环用户管道以这些落下的记录为入口，不自造、不用模型对聊天的事后回忆代替执行事实。链上如何再检索是后续问题，不改变入口绑定。

### 3.5 Conclusion：找规律和关系，不是摘要

从长期 Evidence 中发现稳定规律、作用域、冲突、关联和多跳关系。能力包括：重复、scope、冲突、关系（supports / contradicts / refines_scope / explains / conditions / co_occurs / same_underlying_pattern / temporal_supersedes）、漂移。

例：反感的是重复低收益审核，不是验证本身；核心路径仍要最终验证。  
这还不是 User Model。下一层才问「对理解这个人、对以后工作意味着什么」。

### 3.6 User Model：分域协作判断，不是画像，不是规则

User Model 是：基于长期 Evidence 与 Conclusion，对「这个用户在 Code / Work 中如何做判断、哪些反馈信号有多大价值、哪些工程取舍在什么作用域下稳定成立」形成的专业长期判断。形态是少量、自然语言、工程化、带明确作用域的判断语句。

不合格：「用户不喜欢审核」「用户技术差」。  
合格：「中低风险 Coding 里，对重复同质 Review 容忍低；**不得解释成降低核心链路最终验证**。」

同一人可以同时：前端 code review 信号弱、嵌入式设计 review 信号强、产品行为验收信号强。  
所以它是 **分域协作模型**。User Model 不直接规定 Agent 必须怎么做。

必须分别保存：truthConfidence、scopeConfidence、effectivenessState、confirmationState、推理距离 D0–D3。  
「User Model 可信」≠「这条推断有权约束 Agent」。D2 不得变 hard policy；D3 不持久化。

并行 **Latent Preference Model**：`P(candidate | context, history)`，补全没说完的意图。输出带不确定度的排序，不是再训一个人格网。Evidence / rollback / outcome 是 posterior；Conclusion 不是训练样本；User Model 是 prior / 约束；Policy 永远是下游。必须过 **Ask-or-Act Governor**（置信 × 影响 × 可逆 × 问的成本）；高风险永不因偏好自动过。

### 3.7 Policy：编译器，不是每次让模型临场理解用户

> 模型负责编译，代码负责选择和执行。

User Model 更新或项目大变时才编译；每个 Task 用确定性 Resolver 从 Bundle + Task Context 拿出很小一份 Runtime Pack。在线高频路径不重新跑「个性化推理模型」。

三类粒度同时存在：Global / Project / Task。

| Policy 类型 | 主要用途 | 在线实现 |
|---|---|---|
| Hard Constraint | 不得突破的边界 | 确定性 gate |
| Decision Policy | 条件明确的工程选择 | Decision Table / code |
| Weighted Heuristic | 有倾向但允许工程事实覆盖 | 排序后注入 |
| Prompt Directive | 表达、解释、抽象程度 | Compact Prompt |
| Clarification Gate | 模型不足以可靠决定 | 触发澄清 |

个性化只能发生在：平台安全、项目事实、当前明令 **留出的空间里**。

同一 User Model 还要分成：

- **Personal Agent Policy**：怎么和用户合作（少让他做代码审，让他验产品）
- **Team Translation Policy**：怎么代表他进 Team（Reviewer Agent 把技术审扛走）

并必须标明：explicit / inferred / baseline / recommendation，不能把推断写成用户要求。

### 3.8 真正「下次不一样」的是 BehaviorDelta

可执行的不是「用户喜欢简洁」，是：

```text
decisionPoint
baselineBehavior → adaptedBehavior
expectedBenefit
rollbackBehavior
```

Commitment 有 candidate / trial / shadow / active / paused / retracted。  
Receipt 让人看见范围、变化、撤销。Shadow 只能说「已记录尚未用于执行」。  
Outcome 不以 `task_completed` 当偏好变强；没有明确反馈就保持 unknown。

### 3.9 什么能学、什么不能学（这是 usership 的主体）

**Eligibility：先修自己。**  
「不要编造引用」是质量缺陷 → 修这次 + telemetry，**不进 User Model**。  
授权问题进权限，不进偏好。  
「这次先写结论」停在 Session Intent，不升长期模型。

五层对象：当前意图 / 项目约定 / 长期个人 / 团队约束 / 不可学安全边界。  
升格必须有证据；衰减看 **同类机会**，不是日历——长期没遇到同类任务只是 dormant，不是反证。

**不学习、忘记、撤销是一等能力**：本次不用已有偏好、本次不采集、暂停、纠正、忘记派生策略、清空。无痕任务在 trace 创建时就冻死 extractor，不是先提取再丢。协作护照只迁移用户确认过的脱敏 BehaviorCommitment 模板，不迁移项目事实、权限、未确认推断。

用户可以不回答 Cognition、不看详情、不整理偏好，**基础体验必须独立成立**。

### 3.10 Cognition：怎样认识用户，不是第五个玩具模式

目标是 **每次打扰的长期认知价值**，不是问最多。

- in-task 只在强信号 / 冲突 / 漂移时问；纯缺口不主动问（缺口留给用户打开的第五模式）
- 有日/周顶和连续无视降权
- 必要输入（缺事实、缺授权、高代价分叉）不是 Cognition，可以阻断
- UI：角标 + 轻浮层，不往消息流插重卡

问之前先走：会不会改变当前行为 → 是否已有答案 → 是否必须问才能安全继续 → 能否小步试穿 → 打扰是否值 → 否则保持 unknown。

### 3.11 用户学习在 Learning Agent 里的位置

```text
User Intelligence Plane
  Evidence Fabric（用户侧解释）
  Eligibility Gate
  Conclusion Skill          规律与关系
  User Model Skill          专业判断（少量、分域、带距离）
  Latent Preference         意图补全（并行，不过 Governor 不能动执行）
  Policy Compiler           低频，UM / 项目变化时
  Runtime Policy Resolver   高频，产出本任务 3–7 条
  Decision Governor         Ask / Trial / Act / Stay unknown
  Cognition                 高价值取证，非阻断
  Outcome + Receipt
  Stage II Translation      代表我时的 explicit / inferred / baseline / recommendation
```

「明确纠正快走」仍然存在，但它走的是：

```text
纠正 → Evidence → Eligibility
  → 个性化候选才进 Conclusion / UM / Commitment
  → 质量缺陷当场修、不画像
  → 「仅本次」停在 Session Intent
```

不是跳过整条链写进 `user_rule`。快的是 **治理路径短**，不是 **语义层少**。

## 4. Agent 学习 = 自演化 / 内部进化

来源：A Survey of Self-Evolving Agents（TMLR 01/2026）的组织法 + `open/report/` 九轮机制目录。成熟 CLI 的缺席是空白，不是禁令。

Agent 学习回答四问。这四问就是子系统，不是附录：

| 轴 | 文献问题 | 在 Agent 里是什么 |
|---|---|---|
| **What** | 进化对象 | 记忆、提示/技能、工具、工作流、奖励/检查、路由/结构 |
| **When** | intra vs inter | 任务内三环；任务间三环 |
| **Where** | 改哪一层 | working memory / 长期资产 / 工具面 / 检查器 / 调度 |
| **How** | 模仿、奖励、进化、crosscut | ICL 为主实现介质；语义来自论文，不来自套壳产品 |

实现介质默认 **ICL / 文件资产 / 选择压力**（当前无权重所有权）。  
SFT / RL 在地图上是 Stage III 解禁项（报告 C 级条件：权重所有权、评测 harness、反作弊），**不是「所以 Agent 学习只能写 markdown」。**

### 4.1 When：两口钟都是一等公民

成熟开源是「厚 inter、零 intra」。本 Agent **两口都要有**。

**Intra-test（任务内，文献 Figure 5 上路径）**

任务还在跑时，必须能：

1. **认出局限**（检查失败、反复同类 tool 错、计划卡住、用户当轮纠正）
2. **生成变体**（多计划、多修复、多工具组合、多规则试用）——TT3；近邻是预算化扩展、top-k 历史 + 单点改写，不是假 MCTS
3. **验证**（TT4）：独立 checker / 测试 / critic，不是模型说「我改好了」
4. **更新策略**（TT5，ICL 形态）：本 task 的 working memory、本 attempt 的临时规则、重规划、工具子集、检查 recipe。形态取记忆链 T→M→T、Reflexion 失败才写、Self-Refine 语义判停、异常驱动重计划。**默认不** `exec` 热补丁内核。

Intra 的策略更新写在 **attempt-local / task-local** 层，可以极快。要升成跨任务资产，必须再走过 Inter 的验证门。这样既大胆，又不把当前任务的胡学写进终身记忆。

**Inter-test（任务间，Figure 5 下路径）**

1. **Rollout / 轨迹**：完整、可归因、可关采集
2. **分析**：事实 / 约定 / 方法 / 质量缺陷 / 授权（一次改进可以多种归因）
3. **更新**：记忆合并、规则 counter、skill / workflow 归纳、工具候选、检查器、路由

Inter 可以更重：规则池、工作流归纳、睡眠合并、验证双闸、版本快照、usage 回写。

**双时钟（crosscut 离线 / 在线）：**  
在线 = 流式交互里学；离线 = 历史批次构库。两套都要有。

### 4.2 What / Where：进化对象全部在体内

每一族都有 **产生 → 验证 → 选择 → 生效 → 度量 → 回滚**。没有这一圈，就只是仓库。

| 对象 | 学什么 | 论文近邻（report 已核代码） | 进化压力 |
|---|---|---|---|
| 情景记忆 / 规则 | 事实、失败对比、可执行规则 | 抽取；ExpeL counter；Memento `{q,plan,reward}`；正负双栏 | 验证门 + usage / citation + 假成功更毒 |
| 技能 | 一类任务怎么干 | Voyager 成功才入库；SkillWeaver verified-only、改写即降级复验 | 独立 critic + 复验 |
| 工作流 | 可复用步骤 / 检查序列 | AWM markdown 归纳 | 成功轨迹才归纳 |
| 提示 | prompt patch、文档精炼 | DRAFT / TextGrad「建议 → 应用 → 复评」 | 对照评测 keep-best |
| 工具 | 发现、掌握、轻量自造、绑定 | 发现面已强；创造面：提示词级自造、结晶为工具、文档精炼 | 隔离执行 + 人审安装；安装进程可在宿主，绑定和缺口检测在 Agent 内 |
| 奖励 / 检查 | 「什么叫做成了」本身可进化 | 环境与规则检查；Reflexion；步级归因先用规则 | 检查器版本化；Goodhart 防护 |
| 结构 / 路由 | 用谁、何种顺序、何种模型分工 | 无梯度进化 prompt / memory / tools；多候选 + 断言 | 种群是**资产变体档案**，不是改内核种群 |

「在什么地方学习」= 上表每一行都是学习发生地。不是只在 system prompt 里学。

### 4.3 How：没有选择压力就只有堆积

- 验证门（双闸 / verified-only）
- counter 投票
- 正负双栏
- citation / usage 回写
- keep-best + 失败经验库
- 改写即 stale 再验
- 归因：用过哪些资产、这轮是否被纠正

成熟产品的通病是有生产者无消费者。本 Agent 的第一块地板是 **证据必须被学习消费**。

## 5. 学习控制板：第二调度器（token 与时机）

施工基线里的 Learning Control Board 是种子。本文把它升到产品主角该有的位置：

> **学习控制板是与执行调度器平级的第二调度器。**  
> 它调度的是「学」：何时学、学哪一平面、花多少 token、要不要打断当前任务去 intra。  
> 它不是第二个替用户干活的 Agent，不是人事账本，也不是执行环上的回调插件。

后面所有省 token 的策略都挂在这块板上。没有它，省 token 只能写成「少注入 / 少抽取 / 默认关学习」——那是保守产品，不是本 Agent。

### 5.1 为什么控制板比「学习状态机」重要

两本账只有控制板同时看得见：

- **这一拍花出去的 token**（执行调用、上下文塞了什么、一次 intra 变体、一次 Conclusion、一次抽取）
- **学成之后少花的 token**（用户少解释、方法少错一轮、检查少白跑、上下文少塞废话）

乱学最费 token；不学则每一轮都更费。控制板存在的理由是：

> 该学的时候把 token 砸在学习上，不该学的时候一枚都不给，学成之后执行侧自然变短。

因此控制板支配的第一资源是 **学习预算与时机**，不是提案表格。权限和生产工具仍只认执行调度器。控制板再大胆，也不调度「替用户动手」。

本产品没有把学习做薄的 KPI。控制板应敢于在高收益时花钱（刚说清的协作方式立刻编进政策；同一失败已重复则插入 intra），也敢于在无新证据、采集关闭、预算打光时让学习队列为零——连礼貌性抽取都不要。

### 5.2 和执行调度器怎么并排

```text
                ┌─ 预算 / 时钟 / 生命体征 ─┐
                │                          │
     Execution Scheduler          Learning Scheduler
     （执行调度器）                （学习控制板）
                │                          │
         用户任务队列                  学习工单队列
         模型、工具、审批等待          用户智能工单 /
         取消、恢复                   Agent 进化工单 /
                                      intra / inter / 离线
                │                          │
                └──── Evidence Fabric ─────┘
                       Dispatch Image
                Permission 只认执行调度器
```

执行调度器管用户任务下一步。  
学习控制板管学习下一步。  
两者冲突时由控制板的调度策略裁决，而不是执行说了算。采集关闭则学习队列空转，执行不受影响。学习调度失败默认不得把用户任务卡死——除非控制板明确发出打断类调度令。

执行侧的钩子是 **传感器**（工具结果、用户说话、检查失败、任务结束），用来唤醒控制板。没有新传感器时控制板仍可因自身时钟、积压工单、预算钟而调度。学习不是「执行喊了才动」。

控制板对执行只下调度令，不下「去改那个文件」。调度令的具体集合与协议是后续机制；架构上必须有「向执行请求暂停一拍 / 换新 Image / 隔离验证 / 向用户取证」这类能力，否则第二调度没有牙齿。

### 5.3 它调度两大学习，不合并两大学习

同一调度器，两套工单源：

- 用户智能工单：Eligibility / Conclusion / User Model / Policy 编译 / Cognition / Outcome。产物是合作政策，不是 skill。
- Agent 进化工单：记忆、技能、工作流、工具、检查、路由的变体与验证。产物是方法资产。

两边都向控制板交提案。生命周期可以同一套（草案 → 验证 → 试用 → 启用 → 撤回），**准入不同**：

- 用户明确纠正 → 可快走成 commitment（仍过 Eligibility 和 scope，仍可撤）
- 用户推断 → 候选 + Cognition / 试用
- Agent 方法 → 验证准入才试用；禁止自评转正；假成功更毒
- 工具安装 / 对外贡献 / 改权限 → 永远人审，学习只能提案

LLM 做假设、归纳、变体、批判。控制板做调度、约束、生命体征、准入与回滚。工单怎么排序、预算用什么单位、intra 能否 hold 用户任务——具体机制以后定，不在本节写死。

2026-09-16 第一包机制（已交付，仍未升格为「框架已钉」；详见 `docs/03-学习意志/2026-09-16-Agent学习第一步-讨论脉络.md` 与 `../02-分期工程产出/P05-Experience-Learning-V0.3/2026-09-16-WP-Agent学习调度器与本轮约束卡.md`）：失败不立刻学；工单批准后学习系统打一枪 LLM 出闭集约束卡；代码门 + 下一拍执行事实验收；注入点是下一枪 `promptMessages`，不是改权限或工具表。这是施工收缩，不是把 Dispatch Image 钉死。同日第二轮把它降级为「管子」：课题不再由失败码枚举指定，学习也不另开一轮——见 §5.5。

### 5.4 账本仍要，但是调度的附属（2026-09-16 修正：账本体在控制板，账目归子系统）

控制板仍是学习侧唯一 writer，仍保有：

```text
Proposal / EvidenceBundle / Activation
账本端口（学习侧唯一那本账，子系统经此存取）
Clock（intra-local / inter-online / inter-offline）
```

并存变体、keep-best、shadow 指针、回滚，是为了内部进化有选择压力。**这些是子系统内部的事，不是控制板替它做的事**：方法子系统自己这一族的变体并存、keep-best、shadow 指针、回滚，在子系统内部完成，只经控制板的账本端口存取（账本体只有一本，在控制板）。  
没有调度权的账本，只是人事处。没有账本的调度，无法晋升和撤回。**账本体只在控制板，账目由各子系统自己记——调度是主，账本是从。**

> 修正说明（第二轮）：旧文把 `Variant Archive` 与 keep-best / shadow 一并写在控制板名下，与 §5.5「分层」口径不一致。按产品所有者 2026-09-16 判定：控制板管「谁的账、什么时候能花」，子系统管「这笔账怎么记」。一个概念只有一个写入入口（`AGENTS.md`），故不设第二本变体账。

### 5.5 2026-09-16 第二轮：控制板收缩为「点名 + 额度」（分层）

第一包把管道打通之后，产品所有者对「控制板 ↔ 子系统」这一层做了收缩。这不是把控制板做小，是把谁负责什么分开：**顶上分配额度，子系统自己运转。**

控制板（顶）只做三件事：

- 判断采集开不开、总学习预算还剩多少；
- 发一张工单：本轮叫方法子系统、技能子系统，还是 idle；
- 给一截额度（这一轮子系统可以花多少 token / 调用），然后不参与子系统内部。

控制板**不**替子系统挑资产、不数上场张数、不写提示词、不每回合再打一枪 LLM 去「检索该带哪张」。Agent 学习按 what 分成并列的子系统：方法、技能、工作流、工具、检查、路由；每个子系统在自己的内部再调度。

被点名的子系统内部自转（以方法子系统为例，机理全文见 `docs/03-学习意志/2026-09-16-方法子系统-共枪标签钩子.md`）：

- **机会 ≠ 课题。** 传感器只决定「这一拍被放权」，学什么由执行里的 LLM 定；不再由失败码枚举指定章节。
- **共枪。** 不为学习另开一轮：放权的那一拍，在模型「还在想、还没往工具上走」的提示里加学习意图；输出走固定形状的附加通道，不与 tool_call 抢格式。这一拍就是收工时，仍从同一枪的附加通道收卡。
- **留。** 过门即入 shadow 档案当变体，下一拍工具结果是记账（支持 / 反例），不是删档开关；同 niche 可并存变体，keep-best 挪指针，旧版可回滚。
- **用。** 取卡不跑 LLM：标签 + 上一拍钩子做本地检索；适用范围在抽卡那一枪就写在卡上，上场时免费求值。上场是**编译**：在**方法经验的 token 预算**内装包，编成一条短 system。**预算是硬顶，张数是结果，0 张是正常。**
- **改。** 先检索，只许改命中集，体积有帽。
- **反思。** 全库扫描、去重、优化由用户主动触发，禁止自动。

由此对本文的修订口径：

- §5.2/§5.3 的「控制板调度学习时机、方向、token」保留；其中的「方向」指**点名哪个子系统**，不指替子系统挑哪张资产。
- 「上场必须有硬顶」保留；硬顶的形态从「只准一张」改为「**上场预算**」，张数由预算推出。
- 学习控制板仍是学习侧唯一 writer，**账本体与控制板 Clock 只在控制板（学习侧只此一本账）**：子系统在其账本端口上存取自己那一族资产，**不得自建第二本变体账**。变体的并存与 keep-best、shadow 指针、回滚等**管理动作归子系统内部**（记的仍是同一本账）。
- 跨 turn 上场仍然不许把资产指针推到 `active`：shadow 上场是试用，不是晋升。晋升（`active`）仍要走独立验证门，那是检查子系统与后续资产晋升包的事。

## 6. 证据织物（两大学习的公共地板）

统一织物，分域解释：

| 信号 | 用户学习怎么用 | Agent 学习怎么用 |
|---|---|---|
| 明确纠正 / Cognition 回答 | 强 Evidence | 不自动当方法真理 |
| 工具成败 / 检查输出 | 协作方式线索（如「他在乎全链」） | 方法 / 技能 / 工具的奖励与验证 |
| 用后反馈、返工、撤回 | Outcome，主指标是重复解释率 | 方法有效性，假成功条款 |
| 沉默、停留、未改文件 | 不作为同意 | 不作为成功 |
| 子 Agent 日志 | 不是用户反馈 | 可作方法证据，归因回根 attempt |

Attempt 终态不可变。迟到验证是独立 observation。跨轮纠正用 FeedbackLink，不重开已结束的运行。一次改进可以多种归因；混杂因素必须记录。

用户学习的 Evidence → User Model 与 Agent 的 Episode / 方法资产是两套对象，一块织物。不要互相替换。

用户侧入口已定：绑执行当时落下的身份记录。织物是否作为两路「一次经历再分叉」的同一框架块，见文首「框架级仍未钉」。

## 7. Execution Substrate：传感器 + 被调度的手

执行环必须够强（stream、tool、审批、取消、unknown、恢复对着 `open/` 抄熟轮子）。钩子是打给控制板的 **传感器**，不是学习的主循环。谁在何时学，由第 5 节的学习调度器决定。

执行要认一份由两平面压缩、控制板允许上场的内容。这份「上场物」的名称和内容表框架讨论尚未收口；后文 Dispatch Image 仅为讨论用语。intra 换上场内容是控制板的调度结果，不是执行里写死的 if。

```text
开任务
  User plane 编译：directive + commitments + latent ranking + ask-or-act
  Agent plane 编译：active 记忆 / 技能 / 工作流 / 工具绑定 / 检查 recipe
  → 一份 Dispatch Image（本 attempt 冻结一份；intra 更新产新 image id）

任务中（Intra 钩子，一等）
  每步工具后：过程信号（成败、检查、用户打断）
  识别局限 → 变体 → 验证 → 更新 task-local 策略 → 继续
  用户当轮纠正：进 Evidence，并可改本轮 intent / 触发 intra 更新
  Cognition：非阻断取证
  Impact：高风险才阻断

终态前
  两平面的 required checks 真跑
  失败 → 有界 intra repair（这是 intra 的一种，不是 Agent 学习的全部）

终态后（Inter 钩子，一等）
  轨迹进 Evidence Fabric（可关采集）
  User pipeline 与 Agent pipeline 并行消费
  不阻塞下一任务；但下一任务必须能读到已晋升资产
```

学习允许改的：

- 上下文与示范
- 本轮计划 / 重规划
- 工具可见集与绑定
- 强制检查与 repair recipe
- working memory 与 task-local 规则
- 跨任务资产（经验证门）
- 「什么叫成功」的检查器（经治理）
- Stage II 对子 Agent 的工程代表约束

学习不允许改的：

- Permission 所有权
- 未审批的安装与对外提交
- 内核源码自改
- 把推断写成用户明令
- 采集关闭时从日志偷学

执行层对 Dispatch Image 的解释（检查、绑定、调度、prompt extras 等）是 **execution layer 的局部设计**，不是整个学习架构。usership、intra-test、证据链、对象族进化都不被收成这张解释表。

## 8. 调研怎么用（零件库，不是浅看）

九轮 `open/report/` 对架构的用法：每个 **What × When × How** 格子，用对应维 `80-*-frontier-feasibility.md` 的机制，不靠综述形容词。论文说了不算，**代码实态算**；无 LICENSE 只读思想。

| 格子 | 用哪份 | 取什么 |
|---|---|---|
| 记忆演化 | `memory/` + GDE GD1–4 | 抽取 / 合并 / 装载；欠：值、验证、回灌 |
| 何时学 | `temporal-evolution/` TT1–14 | intra 三环 + inter 三环 |
| 工作流 | `workflow-optimization/` W3 族 | 归纳、规则池；不抄假 MCTS、未开源 RL |
| 工具 | `tool/` | 发现已强；创造 / 掌握用弱化可跑形态 |
| 奖励 | `reward-evolution/` | 文本反馈做深；环境 / 规则检查做真；自奖励为 C |
| 模仿 | `imitation-demonstration-learning/` | 成功示范才回流 |
| 进化 | `agent-evolution/` E20 | 资产变体档案 + 选择 |
| 三轴 | `*-crosscut*` | 在线 / 离线、on / off-policy、outcome + 将来 process |
| 通用域 | `general-domain-evolution/` | 记忆优化先做厚；模型-代理共训为 C |

A 级进近期体内；B 级进架构必有槽；C 级画在地图上并写解禁条件。**画在地图上 ≠ 现在做，也不等于删除。**

`open/01` 成熟 CLI 只补 Execution Substrate。禁止用「成熟产品没做」否决本文的学习能力。

## 9. 和套壳的差

套壳 CLI + 记忆插件：只有 inter 的「写文件、下次塞 prompt」；无 intra 三环；无验证准入；无选择压力；用户学习不是 Evidence → Model → Commitment；Agent 学习不是对象族进化；学习失败 = 功能没了，产品还在。

本架构：用户学习是深 usership（含 latent、Cognition、代表我）；Agent 学习按 what / when / where 内部进化；intra 与 inter 都是一等环；**学习控制板作为第二调度器支配 token 与时机**；证据有消费者；关掉学习是降级的残缺 Agent。

论文方向做在 ICL / 资产 / 选择层，语义用论文，训练层留在地图上。

## 10. 仍开放、但已经住在这张图里

不把这些问题收成「所以先做传统 CLI」。

1. Intra 的 Policy Update 最深到哪：仅 working memory / task-local 规则与重规划 / 同任务下一 turn 新 Dispatch Image。方向：前两档都做，第三档做。不建议默认 Gödel。
2. 已批准检查失败：intra repair 的预算和是否可阻断终态。架构里 **有** 这个钩子；力度待产品拍板。
3. 工具「自造」到哪：提示词级脚本 / 隔离 MCP 包 / 禁止。近期取前两档弱化。
4. Latent 通路进 runtime 的时机：是否先把 Symbolic 闭环做深，Latent 先出 Governor 接口。
5. Policy IR 在新 CLI 里的具体类型——必须是编译 + 确定性解析，不是再让在线模型读一篇用户说明书。
6. 15 个 PolicyDimension 是 Cognition / 编译用的工作词汇，还是长期合同；User Model 正文仍应是少量自然语言判断。
7. Stage II 的 Team Translation 与 Agent 学习的 team routing 如何共用经历、不共用权威。
8. 「完整经历」作为两平面的公共输入，和 v0.3 Episode 是否同一对象。
9. 资产种群规模：先 2–N 个 skill / workflow / prompt 变体 + keep-best。
10. Hermes：最多当旧 skill 仓库过渡，不是进化控制器，不是执行器。
11. 权重级 RL / SFT：C 级在地图上，解禁条件用 GDE / reward 报告，不提前删除 Stage III。
12. D1–D7（载体、控制范围、纠正时效、Agent 经验晋升、检查权力、同轮适应、证据粒度）继续作为执行接点的开放参数，**不得**反过来把第 0–4 节的学习能力删掉。
13. 控制板调度机制（工单排序、预算单位、intra 是否可 hold 用户任务、调度策略本身可否进化）以后单独立项；本节只冻结「第二调度 + token/时机是存在理由」。2026-09-16 第二轮把控制板的工单面收缩为「点名子系统 + 给额度」，子系统内部自转；子系统分层与额度接口仍属开放，见 §5.5。
14. 框架未钉三项见文首：上场物、共同经历/织物是否单独成块、体内 vs 真外围。

## 11. 对施工的含义（本文获批后）

1. 新 CLI 的目标陈述改为 Learning Agent，而不是「追平传统 CLI 再外挂学习」。
2. 用户学习按第 3 节整层进入 runtime，禁止收缩为 `user_rule`。
3. Agent 学习按第 4 节对象族 + 两口钟进入 runtime，禁止收缩为 SKILL.md 注入。
4. 学习控制板按第 5 节实现为第二调度器（调度主、账本从），不收缩为提案状态机，也不做成第二个干活的 Agent。
5. `open/` 成熟 CLI 只用于 Execution Substrate；`open/report/` 用于学习格子的机制选型。
6. 已批准的权限 / 质量 / 许可证门禁继续有效。
7. 与 `TRYLO-CLI-双循环学习控制面架构.md` 冲突时：分权（执行不拥有学习写入、学习不拥有权限）保留；「学习不得进入执行热路径」若被理解成取消 intra / 取消用户政策编译，视为过时理解，用 ADR 修订施工基线后再编码。
