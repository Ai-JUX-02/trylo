# 代码质量 Skills 与 Agent 准入要求

> 状态：待审  
> 适用范围：所有在 `new trylo cli/` 下实现、重构、审查或引入依赖的 Agent  
> 最后更新：2026-09-08

## 已确定方案

仓库已内置 `.agents/skills/trylo-code-quality/SKILL.md`。从 `new trylo cli/` 启动的 Codex 会从 `.agents/skills` 发现仓库级技能，因此它随 checkout 一起可用，不依赖个人机器预装。

任何代码任务必须显式调用 `$trylo-code-quality`。`AGENTS.md` 同时把这条规则设为项目指令；技能负责工作流，确定性 CI 负责不可绕过的机器门禁。二者缺一不可。

## 为什么先自带一个专用技能

通用“代码最佳实践”无法完整覆盖 Trylo 的特殊风险：provider-neutral LOOP、尚待 L01 决定的学习边界、权限只衰减、不可变终态、依赖的架构位置/许可证闭包和分期证据。专用技能把已批准要求变成固定清单，同时阻止 Agent 把讨论稿偷写成合同。

官方当前可安装目录中有安全、CI、Playwright 等专门技能，但没有一个可以直接替代本项目的全栈可读性/可维护性门禁。因此首期不以外部技能替代本地技能。

## 必须与建议的技能层级

| 等级 | Skill | 用途 | 准入 |
| --- | --- | --- | --- |
| 强制 | `trylo-code-quality`（仓库内置） | 每次实现与审查的可读性、维护性、架构、验证和依赖门禁 | 已内置；所有 Agent 必须调用 |
| 强制条件触发 | `repository-vetting` 或等价审计流程 | 第三方仓库可能成为核心 runtime、侵入性依赖或长期架构承诺时 | 必须完成 hard-gate 报告；技能本身未分发时按仓库模板执行 |
| P03 前建议引入 | `security-best-practices` | 工具、权限、shell、路径和网络边界审查 | 安装前先审计技能来源和许可证 |
| P03 前建议引入 | `security-threat-model` | 写出资产、信任边界、攻击面和缓解方案 | 安装前先审计；不能替代实现测试 |
| CI 阶段建议 | `gh-fix-ci` | 诊断 CI 失败 | 只修真实根因，不允许降低门禁 |
| P08 建议 | `playwright` | Desktop/Web UI 黑盒交互验证 | 仅负责 UI 证据，不替代 runtime 合同测试 |

安全类技能处理安全，不能被称为“更好的代码质量技能”来取代可读性与维护性审计。

## “或者更好”的认定标准

替代技能必须在 ADR 中逐项映射并证明至少覆盖：

1. 可读性作为第一审查项和发布阻断项；
2. 单向架构与唯一状态所有者；
3. provider-neutral、UI-neutral 的核心边界；
4. 学习 LOOP 与外围分析的强隔离；
5. 错误、取消、timeout、unknown、恢复和幂等；
6. 权限不得被模型、学习或扩展放大；
7. 公共合同、状态机与事件的测试；
8. 所有生产/开发/构建/测试/传递依赖的许可闭包；
9. 当前工期证据、风险和回滚记录；
10. 明确 stop condition，不能在门禁失败时宣告完成。

任何一项较弱都不算“更好”。在 ADR 批准前，本地技能继续强制使用。

## Agent 开工准入

Agent 在第一处代码修改前必须提交或回复以下开工卡：

```text
当前阶段与技术规格：
已加载 $trylo-code-quality：是/否
行为合同：
涉及模块与依赖方向：
状态所有者：
许可证变化：无 / 有（链接审计）
测试和故障场景：
预计产出文档位置：
```

缺少任一项不得开始改生产代码。纯文档勘误可以简化，但架构决策和依赖清单不属于勘误。

## Review Agent 准入

审计者不得只运行测试或复述 diff。必须：

- 从入口跟踪至少一条成功路径和一条失败/取消路径；
- 指出状态所有者与提交点；
- 检查新增抽象是否只有一个真实调用者、是否制造第二来源；
- 检查 public event/schema 的 producer 与 consumer；
- 检查依赖来源、固定版本和传递许可；
- 按优先级列 findings，先报告可读性/可维护性问题；
- 在没有 finding 时也列出已核验范围和未覆盖范围。

## Skill 更新纪律

本地 skill 是受版本控制的工程资产。修改它需要：

- 说明触发场景为何变化；
- 用至少一个正常任务和一个应阻断任务验证；
- 不删除既有门禁，除非 ADR 证明被更强的确定性检查替代；
- 更新本文件与 `AGENTS.md` 的引用；
- 在 P00 产出目录保存验证记录。

Skill 只能改善执行一致性，不能取代架构评审、CI、真实平台测试或维护者判断。
